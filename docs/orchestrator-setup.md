# Orchestrator setup (new projects only)

Follow `d2r-orchestrator`, the agent contract and [workflow](ai-workflow.md). Resume the latest handoff instead of repeating setup for an existing project.

1. Confirm creator permission for a classic port before proceeding; record who, where and terms (credit, publishing). Stop if missing. Download into a new empty folder; never execute downloaded installers/executables; Python readers use `-I`. Record filename, size and SHA-256.
2. Delegate source inventory to an implementer: classic version, own DLL/patched DLL/loader, tables, strings, art, maps and tools; write `docs/source-inventory.md`. Skip source steps for a new mod.
3. Confirm owner decisions: mod name (folder, saves, installer), hosting, public/private and timing, provider/model access. Record decisions in ADRs/notes. Discover live provider/model names before routing. Put machine/project settings in existing configuration; keep secrets in owner-managed home files.
4. Create the repo, scaffold `AGENTS.md`, `docs/agents/`, `.d2r-project.toml`, `docs/PLAN.md`, `docs/deviations.md` for a port, changelog fragments and initial changelog. Install privacy hooks from a toolkit clone, not the plugin cache; see the orchestrator skill. Set up frozen slots with separate saves; exclude the owner's game.
5. Choose phases in order: setup; tools (extractors/converters/ID and string mapping/validation); data (D2R tables, zero errors); engine triage (each source code change: data/plugin/D2R already has it/drop); plugin (data cannot express; follow signature and image policy in `d2r-engine`); graphics (vanilla stand-ins first, custom art last); release (installer/hosting/changelog/release pages). New systems may need an RE spike earlier.
6. Keep one issue per job, duplicates closed before work, progress in issues and roadmap in PLAN. For ports keep deviations and owner-approved ADRs.
7. Route strongest models to orchestration/review, difficult RE, crash and release-critical fixes; mid-tier to ordinary implementation and judgement-heavy docs; small models to mechanical tasks/inventories. Spread heavy lanes across available accounts; alternate main implementer providers where available. See workflow section 4. Use child tasks with unique request IDs, not top-level sessions.
8. Record lessons as cause, evidence and canonical reference, not copied prompt rules. See workflow section 10. Examples: D2R-only row IDs, reserved skill slots, loader/crash logs on the exact image, mortal-character damage reproduction, stale plugin/default mod, duplicate fixes.
